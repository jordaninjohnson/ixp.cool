The idea

Build the boring parts well.

Digital signage is easy to demo and harder to operate. Real buildings introduce unreliable networks, replacement hardware, changing users, expired content, maintenance, and support handoffs. IXP is being designed for that reality.

01 / OPEN

Open from the core

The goal is useful, understandable software with a path to open-source publication. The application source and public license terms have not been released yet.

02 / OPERABLE

Built past the demo

Deployment, logs, health, backups, upgrades, and recovery belong in the product story — not in a forgotten checklist after launch.

03 / HUMAN

Made for real operators

Software should leave the next person with something understandable. Clear documentation and simple architecture are features.

Verified scope

Real progress. Clear boundaries.

IXP is a developer-run prototype with automated tests, not yet software ready to operate public-facing displays.

WORKING LOCALLY

Inventory foundations

  • PostgreSQL schema, fictional sample data, and database contract tests
  • FastAPI creation and browsing for organizations, buildings, locations and logical screens
  • React/TypeScript admin interface for the inventory hierarchy
  • Organization-wide screen inventory and per-building status counts
NOT RELEASED

Before real deployments

  • Authentication, permissions and role-based access control
  • Physical device provisioning and actual display playback
  • Content management, scheduling and offline behavior
  • Production installation, recovery procedures and real-world pilots

Security boundary: IXP currently has no API authentication. Use fictional data on loopback only. The application repository is private, and no official public license or product release has been issued.

Roadmap

One useful layer at a time.

Milestones reflect engineering scope, not published releases. Security and operator reliability come before live deployment.
